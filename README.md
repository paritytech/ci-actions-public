# ci-actions-public

Reusable GitHub Actions and workflows that Parity shares publicly. Repositories
outside the organisation may call them too.

Pin a commit SHA rather than a branch when you call anything here.

## vertex-ai-review

Reusable workflow and composite action that post an advisory pull request review
generated by Vertex AI (Gemini). The action calls the Vertex `generateContent`
API straight from the runner. The prompt lives beside the action, in
`.github/actions/vertex-ai-review/prompt.md`.

The action never checks out or runs pull request code. It reads the diff over
the GitHub API. That is what lets it review a fork safely from a job that holds
credentials.

Cost control rests on the model choice, on `max_diff_bytes` and on
`max_output_tokens`. The on and off switch is the workflow file in the calling
repo.

### 1) Auto PR review (on PR events)

```yaml
name: Vertex AI Review

on:
  pull_request_target:
    types: [opened, reopened, synchronize, ready_for_review]

# A called workflow cannot hold more permission than its caller grants, so these
# three must appear here even though the called workflow declares them too.
permissions:
  contents: read
  pull-requests: write
  id-token: write

jobs:
  review:
    uses: paritytech/ci-actions-public/.github/workflows/vertex-ai-review.yaml@main
    with:
      vertex_project: your-gcp-project
    secrets:
      GCP_SA_VERTEX_AI_REVIEW: ${{ secrets.GCP_SA_VERTEX_AI_REVIEW }}
      GCP_WIP_VERTEX_AI_REVIEW: ${{ secrets.GCP_WIP_VERTEX_AI_REVIEW }}
```

`pull_request_target`, not `pull_request`, and this is not optional — the WIF
provider only mints tokens for `pull_request_target` and `issue_comment` events,
so a `pull_request` trigger fails authentication. Two reasons it is also the
right choice:

- `pull_request` gives a fork's PR no secrets at all, so it could never review
  external contributions — the case that motivated this action.
- GitHub runs `pull_request_target` workflows from the **default branch**, so a
  contributor cannot alter the reviewer by pushing a branch.

It is safe here only because the action never checks out or executes PR code —
see [Security posture](#security-posture), and read it before changing the
trigger.

### 2) Manual PR review (comment trigger)

```yaml
name: Vertex AI Review (Manual)

on:
  issue_comment:
    types: [created]

permissions:
  contents: read
  pull-requests: write
  id-token: write

jobs:
  review:
    uses: paritytech/ci-actions-public/.github/workflows/vertex-ai-review.yaml@main
    with:
      vertex_project: your-gcp-project
      comment_trigger: "/aireview"
    secrets:
      GCP_SA_VERTEX_AI_REVIEW: ${{ secrets.GCP_SA_VERTEX_AI_REVIEW }}
      GCP_WIP_VERTEX_AI_REVIEW: ${{ secrets.GCP_WIP_VERTEX_AI_REVIEW }}
```

The comment must be on a PR, and the commenter must be a `MEMBER`, `OWNER`, or
`COLLABORATOR` — an external contributor cannot spend Vertex budget.

### Inputs

| Input               |  Type   | Required | Default            | Description                                                                                     |
| ------------------- | :-----: | :------: | ------------------ | ----------------------------------------------------------------------------------------------- |
| `vertex_project`    | string  |   Yes    | —                  | GCP project hosting the Vertex endpoint. It holds the quota and the bill.                        |
| `vertex_location`   | string  |    No    | `global`           | `global` uses the unprefixed multi-region host; anything else becomes a host prefix.            |
| `vertex_model`      | string  |    No    | `gemini-3.7-flash` | Publisher model id. `gemini-3-pro` costs more and reasons harder.                               |
| `thinking_level`    | string  |    No    | `medium`           | Gemini 3 thinking budget: `low`, `medium`, `high`. Empty leaves the model default (`medium`).    |
| `seed`              | string  |    No    | `1`                | Sampling seed. A fixed value asks for the same answer to the same diff. Change it for a fresh take. |
| `prompt_path`       | string  |    No    | `""`               | Repo-relative prompt template. Needs `checkout_base: true`. Empty uses the action's `prompt.md`. |
| `checkout_base`     | boolean |    No    | `false`            | Check out the **base** repo (never the PR head) so `prompt_path` can resolve.                    |
| `max_diff_bytes`    | string  |    No    | `400000`           | Diff bytes sent to the model. Above this the diff is truncated and the model is told so.        |
| `review_event`      | string  |    No    | `COMMENT`          | `COMMENT` never blocks a merge.                                                                 |
| `comment_trigger`   | string  |    No    | `@aireview`        | Trigger phrase for `issue_comment` events.                                                      |
| `runs_on`           | string  |    No    | `ubuntu-latest`    | Runner label.                                                                                   |

### Gemini 3 notes

Two defaults exist because of how Gemini 3 models behave, and both are easy to
get wrong when copying config from a 2.5-era setup:

- **No `temperature` is sent.** Google's guidance for Gemini 3 is to leave
  temperature at its default of 1.0; lowering it risks looping and degraded
  reasoning. The `temperature` input is therefore empty by default, and an empty
  value means the field is omitted from the request entirely rather than sent as
  a number. Only set it if you have a reason to.
- **`thinking_level: medium`, `max_output_tokens: 16384`.** Thinking tokens are
  drawn from `max_output_tokens` and are then dropped. `review.py` filters parts
  carrying `thought: true`, since they are not review content. A thinking level
  that outgrows the budget returns no review text, which shows as
  `finishReason=MAX_TOKENS` and costs a retry. The budget is a ceiling and not a
  spend, so a generous one is cheap: a retry re-sends the whole diff and you pay
  the input twice. Note the retry doubles whatever you set, so `16384` makes the
  second attempt `32768`.

### Why two runs read the same

Repeated reviews of one pull request used to differ in shape as well as in
content: `-` bullets in one run and `*` in the next, an invented `Reliability`
heading, item counts drifting. Three things hold the shape still now.

- **The response is schema-constrained.** `generationConfig` carries
  `responseMimeType: application/json` and a `responseSchema` whose `category`
  field is an enum of `Correctness`, `Security`, `Tests`, `Maintainability`. A
  fifth category cannot come back.
- **`review.py` renders the markdown.** `render_review` writes every heading,
  every bullet and the category order. The model supplies prose for `title`,
  `impact` and `fix` alone. Caps live in one place: three summary points, three
  findings per category.
- **A fixed `seed`.** With the same diff and the same parameters the model tries
  to return the same answer. Google documents this as best effort, so treat it
  as a strong nudge.

What still moves is which findings the model promotes. It ranks, and ranking
shifts between runs. Bump `seed` when you want a deliberately fresh opinion.

One consequence for the retry path. A budget cut now leaves the JSON object
unterminated. `extract-review` treats a parse failure with
`finishReason=MAX_TOKENS` as retryable and prints `retry`; a parse failure with
any other finish reason fails the step, because a second call would not help.

### Prerequisites

The calling repo needs a Google service account reachable over Workload Identity
Federation, and two repository secrets:

| Secret | Holds |
| --- | --- |
| `GCP_SA_VERTEX_AI_REVIEW` | the service account email |
| `GCP_WIP_VERTEX_AI_REVIEW` | the full WIF provider resource name |

Neither value is a credential. One is an email and the other is a resource path.
Both are useless without a GitHub OIDC token from a repository the provider
accepts.

Give that service account one permission on the Vertex project:
`aiplatform.endpoints.predict`. It is the permission the `generateContent` API
checks. `roles/aiplatform.user` also works and grants several hundred
permissions, most of them able to create or delete, for a job that sends one
POST. A custom role with the single permission is the better fit.

Scope the Workload Identity Federation provider as tightly as your setup allows.
Pinning the `event_name` claim to `pull_request_target` and `issue_comment` is
worth doing, because GitHub runs workflows for both of those events from the
default branch alone. A contributor who pushes a branch then cannot mint a token.

### Degraded inputs

The action never fails a run just because the diff is awkward:

- **Diff over `max_diff_bytes`** — truncated, and the prompt tells the model it
  is seeing a partial change.
- **PR over 300 files** — GitHub answers the diff endpoint with HTTP 406, so the
  action falls back to the changed-file list with per-file line counts and tells
  the model to comment on shape and risk only.

Which of the three happened is exposed as the action's `mode` output (`full`,
`truncated`, `file-list`).

### Security posture

- **No PR code is checked out or executed.** The action reads the diff over the
  GitHub API and sends it to Vertex. That is what makes it safe to run from
  `pull_request_target`, where the job holds credentials: there is no PR-authored
  script, build file, or dependency for a fork to get executed.
- **Prompt injection is still possible** and no amount of prompt hardening fixes
  it. The PR title, body, and diff are fenced as untrusted data and the model is
  told to report injection attempts as a Security finding, but a determined
  author can still steer the review. Every posted review therefore carries
  `🤖 AI-generated review — advisory only, not a substitute for human review.`
  The reviewer who approves the PR owns the approval.
- **Nothing is logged.** `review.py` prints status lines only — no prompts,
  diffs, tokens, or response bodies reach the run log.
- **Attacker-controlled strings never touch shell.** The PR title and body go
  from the API into a JSON file and from there into the prompt; they are never
  interpolated into a `run:` block or a step output.
- **Single-pass templating.** A PR titled `{{DIFF}}` stays literal instead of
  expanding.

### How it works

`review.py` has four subcommands. The composite action calls them in order and
passes files between the steps.

```
                        action.yml (composite)
                                 │
                  ┌──────────────┴───────────────┐
                  │   WIF auth → access_token    │
                  └──────────────┬───────────────┘
                                 │
   ┌─────────────────────────────▼────────────────────────────────┐
   │ review.py fetch-diff                                         │
   │                                                              │
   │ GET /pulls/{n}  Accept: +json     → title, body ─────────────┼──► pr.meta.json
   │ GET /pulls/{n}  Accept: v3.diff                              │
   │       │                                                      │
   │       ├─ 406 ──► GET /pulls/{n}/files   (paged, 100/page)    │
   │       │          format_file_list()      mode = file-list    │
   │       ├─ 200 ──► truncate_bytes(MAX_DIFF_BYTES)              │
   │       │                                  mode = truncated    │
   │       │                                       or full        │
   │       └─ else ─► ReviewError                                 │
   │                                                              │
   │ text ────────────────────────────────────────────────────────┼──► pr.diff
   │ mode ────────────────────────────────────────────────────────┼──► GITHUB_OUTPUT
   └─────────────────────────────┬────────────────────────────────┘
                                 │
   ┌─────────────────────────────▼────────────────────────────────┐
   │ review.py build-request                    attempt 1, then 2 │
   │                                                              │
   │   prompt.md ──┐                                              │
   │ pr.meta.json ─┼─► diff_note(mode)                            │
   │      pr.diff ─┘   render_prompt()   one pass, 6 tokens       │
   │                   build_payload()   maxOutputTokens          │
   │                                     responseMimeType + schema │
   │                                     seed          if set      │
   │                                     temperature   if set      │
   │                                     thinkingLevel validated   │
   │                                                              │
   │ payload ─────────────────────────────────────────────────────┼──► req.json
   └─────────────────────────────┬────────────────────────────────┘
                                 │
                  ┌──────────────▼───────────────┐
                  │ curl POST req.json           │
                  │ url from: review.py          │──► resp.json
                  │            vertex-url        │
                  │ Bearer access_token          │
                  └──────────────┬───────────────┘
                                 │
   ┌─────────────────────────────▼────────────────────────────────┐
   │ review.py extract-review                                     │
   │                                                              │
   │ json.load(resp.json)  ── bad JSON ──► ReviewError            │
   │ candidates[0]         ── none ──────► ReviewError blockReason │
   │ drop parts with thought:true                                 │
   │ json.loads the text that is left                             │
   │            ── truncated + MAX_TOKENS ──► stdout: retry        │
   │            ── truncated otherwise ─────► ReviewError          │
   │ render_review()  headings, order and bullets come from here   │
   │                                                              │
   │ text ────────────────────────────────────────────────────────┼──► review.txt
   │ needs_retry(finishReason, length) ──► stdout: ok | retry     │
   └─────────────────────────────┬────────────────────────────────┘
                                 │
              retry ─────────────┤  attempt 2 doubles the token budget
                                 │
                 ok ─────────────┤
                                 │
                  ┌──────────────▼───────────────┐
                  │ actions/github-script        │
                  │ disclaimer + review.txt      │
                  │ pulls.createReview(COMMENT)  │
                  └──────────────────────────────┘
```

Files that pass between the steps:

| File | Written by | Read by |
| --------------- | --------------- | --------------- |
| `pr.meta.json`  | fetch-diff      | build-request   |
| `pr.diff`       | fetch-diff      | build-request   |
| `req.json`      | build-request   | curl            |
| `resp.json`     | curl            | extract-review  |
| `review.txt`    | extract-review  | github-script   |

Every failure raises `ReviewError`. The CLI catches it, writes one line to
stderr, and exits 22.

### Tests

`review.py` is stdlib-only and holds every parsing decision, so it is unit
tested — `.github/workflows/test-vertex-ai-review.yaml` runs the suite on any
change to the action:

```bash
cd .github/actions/vertex-ai-review/scripts && python3 -m unittest discover -p 'test_*.py'
```
